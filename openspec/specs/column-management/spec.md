# column-management Specification

## Purpose
ユーザーがカラムを追加・削除し、各カラムの基本操作(手動更新・戻る・先頭へ)と最終更新時刻をカラムヘッダから扱えるようにする。

## Requirements

### Requirement: カラム追加時の入力解釈
カラム追加時、システムはユーザー入力を次のように解釈しなければならない(MUST)。数字のみの入力は種別 `list` として `https://x.com/i/lists/<数字>` を生成する。`x.com/i/lists/...` または `twitter.com/i/lists/...` 形式は種別 `list` として `https://x.com/` に正規化した URL を生成する。`@username` は種別 `profile` として `https://x.com/username` を生成する。`search:キーワード` は種別 `search` として `https://x.com/search?q=<URLエンコードしたキーワード>&f=live` を生成する。`home` は種別 `home` として `https://x.com/home` を生成する。その他の `x.com` の URL は種別 `custom` としてそのまま使用する。いずれにも当てはまらない入力はエラーとし、カラムを追加してはならない(MUST NOT)。

#### Scenario: リストIDのみを入力
- **WHEN** ユーザーが `1234567890` を入力して追加する
- **THEN** 種別 `list`、URL `https://x.com/i/lists/1234567890` のカラムが追加される

#### Scenario: twitter.com のリストURLを入力
- **WHEN** ユーザーが `https://twitter.com/i/lists/1234567890` を入力して追加する
- **THEN** URL が `https://x.com/i/lists/1234567890` に正規化された種別 `list` のカラムが追加される

#### Scenario: スキームなしのリストURLを入力
- **WHEN** ユーザーが `x.com/i/lists/1234567890` を入力して追加する
- **THEN** URL `https://x.com/i/lists/1234567890` の種別 `list` のカラムが追加される

#### Scenario: ユーザー名を入力
- **WHEN** ユーザーが `@sudabon` を入力して追加する
- **THEN** 種別 `profile`、URL `https://x.com/sudabon` のカラムが追加される

#### Scenario: 検索キーワードを入力
- **WHEN** ユーザーが `search:electron 開発` を入力して追加する
- **THEN** 種別 `search`、URL `https://x.com/search?q=electron%20%E9%96%8B%E7%99%BA&f=live` のカラムが追加される

#### Scenario: ホームを入力
- **WHEN** ユーザーが `home` を入力して追加する
- **THEN** 種別 `home`、URL `https://x.com/home` のカラムが追加される

#### Scenario: 空の検索キーワード
- **WHEN** ユーザーが `search:` のみを入力して追加する
- **THEN** エラーメッセージが表示され、カラムは追加されない

#### Scenario: 任意の x.com URLを入力
- **WHEN** ユーザーが `https://x.com/search?q=electron&f=live` を入力して追加する
- **THEN** 種別 `custom`、入力どおりの URL のカラムが追加される

#### Scenario: 解釈できない入力
- **WHEN** ユーザーが `hello world` や `https://example.com/` を入力して追加する
- **THEN** エラーメッセージが表示され、カラムは追加されない

### Requirement: カラムの追加と削除
ユーザーはツールバーからカラムを追加し、カラムヘッダからカラムを削除できなければならない(MUST)。追加したカラムは右端に配置され、デフォルト設定(幅・更新間隔・ズーム)で作成されなければならない(MUST)。構成の変更は直ちに設定ファイルへ保存されなければならない(MUST)。

#### Scenario: 3本のリストを追加
- **WHEN** ユーザーがリストを3本追加する
- **THEN** 3つのカラムが追加順に左から横に並んで表示される

#### Scenario: カラムを削除
- **WHEN** ユーザーがカラムヘッダの削除ボタンを押す
- **THEN** そのカラムが画面から消え、残りのカラムが詰めて表示され、設定ファイルからも削除される

### Requirement: カラムヘッダの基本操作
各カラムの上部に、タイトル、最終更新時刻(「2分前」のような相対表記)、および手動更新・戻る・先頭へ・削除のボタンを表示しなければならない(MUST)。「戻る」と「先頭へ」は、カラムが基準URL以外を表示している間のみ表示しなければならない(MUST)。

#### Scenario: 手動更新
- **WHEN** ユーザーがカラムヘッダの手動更新ボタンを押す
- **THEN** そのカラムが再読み込みされ、最終更新時刻が更新される

#### Scenario: 詳細画面から先頭へ戻る
- **WHEN** カラム内で投稿をクリックして詳細画面を表示中に、ユーザーが「先頭へ」を押す
- **THEN** カラムはそのカラムの基準URLを表示し、「戻る」「先頭へ」ボタンが非表示になる

#### Scenario: 詳細画面から戻る
- **WHEN** カラムが詳細画面を表示中に、ユーザーが「戻る」を押す
- **THEN** カラムは直前のページへ戻る

#### Scenario: 最終更新時刻の表示
- **WHEN** カラムが2分前に再読み込みされた
- **THEN** カラムヘッダに「2分前」と表示される

### Requirement: 全カラム更新
ツールバーから全カラムを手動で再読み込みできなければならない(MUST)。

#### Scenario: 全カラム更新
- **WHEN** ユーザーがツールバーの全カラム更新ボタンを押す
- **THEN** すべてのカラムが再読み込みされる

### Requirement: カラムの並べ替え
ユーザーはカラムヘッダをドラッグ&ドロップしてカラムの順序を変更できなければならない(MUST)。変更後の順序は直ちに保存され、再起動後も保持されなければならない(MUST)。

#### Scenario: ドラッグで並べ替え
- **WHEN** ユーザーが1番目のカラムのヘッダを3番目の位置へドラッグ&ドロップする
- **THEN** カラムの表示順が入れ替わり、カラム本体もヘッダと同じ位置に移動する

#### Scenario: 並べ替えの永続化
- **WHEN** カラムを並べ替えた後にアプリを再起動する
- **THEN** 並べ替え後の順序でカラムが表示される

### Requirement: カラムごとの設定
ユーザーはカラムヘッダの設定ボタンから、そのカラムの幅(300〜640px)・更新間隔(60〜3600秒)・ズーム(0.5〜1.5)を変更できなければならない(MUST)。範囲外の値は受け付けてはならない(MUST NOT)。変更は直ちに表示・自動更新に反映され、保存されなければならない(MUST)。

#### Scenario: カラムごとに異なる値
- **WHEN** ユーザーがカラムAを幅 480px・間隔 300 秒・ズーム 0.9、カラムBを幅 320px・間隔 60 秒・ズーム 1.2 に設定し再起動する
- **THEN** 各カラムが設定どおりの幅・ズームで表示され、それぞれの間隔で自動更新される

#### Scenario: 範囲外の値
- **WHEN** ユーザーが更新間隔に 30 秒を入力する
- **THEN** エラーが表示され、設定は変更されない

### Requirement: デフォルト設定
ユーザーはツールバーの設定から、新規カラムに使うデフォルトの幅・更新間隔・ズームを変更できなければならない(MUST)。デフォルト値の変更は既存カラムの値を変更してはならない(MUST NOT)。

#### Scenario: デフォルト幅の変更
- **WHEN** ユーザーがデフォルト幅を 420px に変更してからカラムを追加する
- **THEN** 新しいカラムは幅 420px で追加され、既存カラムの幅は変わらない

### Requirement: タイトルの編集
ユーザーはカラムヘッダのタイトルをダブルクリックして編集できなければならない(MUST)。確定した値は保存され、空文字で確定した場合は編集前のタイトルを維持しなければならない(MUST)。

#### Scenario: タイトルを変更
- **WHEN** ユーザーがタイトルをダブルクリックし「技術ニュース」と入力して確定する
- **THEN** ヘッダのタイトルが「技術ニュース」になり、再起動後も保持される

#### Scenario: 編集のキャンセル
- **WHEN** ユーザーがタイトル編集中に Escape を押す
- **THEN** タイトルは編集前のまま変わらない

### Requirement: カラム単位の一時停止
ユーザーはカラムヘッダからカラムの自動更新を一時停止・再開できなければならない(MUST)。一時停止状態はヘッダで識別でき、保存されなければならない(MUST)。一時停止中も手動更新は実行できなければならない(MUST)。

#### Scenario: 一時停止中は自動更新しない
- **WHEN** ユーザーがカラムを一時停止し、先頭表示のまま更新間隔以上が経過する
- **THEN** そのカラムは自動では再読み込みされない

#### Scenario: 再開
- **WHEN** 一時停止中のカラムをユーザーが再開する
- **THEN** 以後の更新判定で再び自動更新の対象になる

### Requirement: 全カラムの一時停止と再開
ユーザーはツールバーから全カラムの自動更新を一括で一時停止・再開できなければならない(MUST)。一括一時停止は全カラムの一時停止状態を有効にし、一括再開は全カラムの一時停止状態を解除しなければならない(MUST)。

#### Scenario: 全カラム一時停止
- **WHEN** ユーザーがツールバーの全カラム一時停止を押す
- **THEN** すべてのカラムが一時停止状態になり、自動更新されなくなる

#### Scenario: 全カラム再開
- **WHEN** 一部または全部のカラムが一時停止中にユーザーが全カラム再開を押す
- **THEN** すべてのカラムの一時停止が解除される
