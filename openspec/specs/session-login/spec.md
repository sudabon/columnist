# session-login Specification

## Purpose
ユーザーが x.com に一度ログインするだけで全カラムを利用でき、再起動後もログイン状態が保たれるようにする。資格情報には一切触れない。

## Requirements

### Requirement: 共有永続セッション
全カラムは単一の永続セッション(パーティション `persist:columnist-default`)を共有しなければならない(MUST)。

#### Scenario: 一度のログインで全カラムが利用できる
- **WHEN** ユーザーがログインした後に複数のカラムを追加する
- **THEN** すべてのカラムがログイン済みの状態で表示される

#### Scenario: 再起動後もログイン不要
- **WHEN** ログイン済みの状態でアプリを終了し再起動する
- **THEN** ログイン画面は表示されずカラム画面が表示される

### Requirement: cookie の有無のみによるログイン判定
システムは起動時、セッションに `x.com` ドメインの `auth_token` cookie が存在するかどうかのみを確認してログイン状態を判定しなければならない(MUST)。cookie の値を読み取ったり保存してはならない(MUST NOT)。

#### Scenario: 未ログイン時はログイン画面を表示
- **WHEN** `auth_token` cookie が存在しない状態で起動する
- **THEN** ウィンドウ全体に `https://x.com/i/flow/login` が表示される

#### Scenario: ログイン済み時はカラム画面を表示
- **WHEN** `auth_token` cookie が存在する状態で起動する
- **THEN** 保存済みのカラム構成でカラム画面が表示される

### Requirement: ログイン完了の検知と画面遷移
ログイン画面表示中に `auth_token` cookie が出現した場合、システムはログイン画面を破棄してカラム画面へ遷移しなければならない(MUST)。資格情報の入力はユーザー自身が行い、システムは保存・自動入力をしてはならない(MUST NOT)。

#### Scenario: ログイン後にカラム画面へ移る
- **WHEN** ユーザーがログイン画面でユーザー名・パスワード(・2FA)を入力しログインに成功する
- **THEN** ログイン画面が閉じ、カラム画面が表示される

### Requirement: ログイン方法の案内
README は、X のユーザー名+パスワード(+2FA)でのログインを前提とし、外部IdP(Google 等)によるログインは組み込みブラウザでブロックされる可能性があることを記載しなければならない(MUST)。

#### Scenario: README にログイン方法がある
- **WHEN** README を確認する
- **THEN** ユーザー名+パスワードでのログインを前提とする旨が記載されている
