# list-picker Specification

## Purpose
自分のリストを、IDやURLを入力せずに追加できるようにする。リストの選択は x.com の公式画面上でユーザー自身が行い、アプリはその画面の URL だけを見て追加する。

## Requirements

### Requirement: リスト選択画面を開く
ログイン済みの状態でユーザーがツールバーの「リストから選ぶ」を押した場合、システムはツールバーの下の領域全体に x.com の画面(リスト選択画面)を開かなければならない(MUST)。リスト選択画面はカラムと同じセッションを使い、ログイン済みの状態で表示しなければならない(MUST)。リスト選択画面が開いている間、カラムヘッダとカラムは隠れていてよいが、カラムの自動更新タイマーは継続しなければならない(MUST)。

#### Scenario: リスト選択画面を開く
- **WHEN** ユーザーがツールバーの「リストから選ぶ」を押す
- **THEN** ツールバーの下に x.com の画面が表示され、ツールバーには「このリストを追加」と「キャンセル」が表示される

#### Scenario: 二重に開かない
- **WHEN** リスト選択画面が開いている状態で、再度リスト選択画面を開く操作が行われる
- **THEN** リスト選択画面は1つのまま増えない

#### Scenario: ウィンドウのリサイズに追従
- **WHEN** リスト選択画面を開いた状態でウィンドウサイズを変更する
- **THEN** リスト選択画面はツールバーの下の領域全体に合わせて再配置される

### Requirement: リストのページを開いている間だけ追加できる
「このリストを追加」は、リスト選択画面が `https://x.com/i/lists/<数字>` のページを表示している間だけ押せなければならない(MUST)。それ以外のページを表示している間は押せず、リストを開くよう案内を表示しなければならない(MUST)。判定はリスト選択画面の URL のみで行わなければならない(MUST)。

#### Scenario: リスト一覧を表示中
- **WHEN** リスト選択画面が自分のリスト一覧のページを表示している
- **THEN** 「このリストを追加」は押せず、リストを開くよう案内が表示される

#### Scenario: リストを開いた
- **WHEN** ユーザーがリスト選択画面でリストをクリックし、`https://x.com/i/lists/1234567890` が表示される
- **THEN** 「このリストを追加」が押せるようになる

#### Scenario: リストのメンバー一覧など下位ページ
- **WHEN** リスト選択画面が `https://x.com/i/lists/1234567890/members` を表示している
- **THEN** 「このリストを追加」は押せない

### Requirement: リストをカラムとして追加する
ユーザーが「このリストを追加」を押した場合、システムは表示中のリストを、ID入力時と同じ規則(種別 `list`、URL `https://x.com/i/lists/<数字>`、タイトル「リスト <数字>」、デフォルトの幅・間隔・ズーム)でカラムとして右端に追加し、保存しなければならない(MUST)。追加後はリスト選択画面を閉じ、追加したカラムが見える位置までスクロールしなければならない(MUST)。

#### Scenario: リストを追加
- **WHEN** リスト選択画面で `https://x.com/i/lists/1234567890` を表示中に「このリストを追加」を押す
- **THEN** URL `https://x.com/i/lists/1234567890`、タイトル「リスト 1234567890」のカラムが右端に追加・保存され、リスト選択画面が閉じる

#### Scenario: 追加ボタンを押した直後にページが変わっていた
- **WHEN** 「このリストを追加」を押した時点で、リスト選択画面がリスト以外のページへ遷移していた
- **THEN** カラムは追加されず、リスト選択画面は開いたままで、リストを開くよう案内が表示される

### Requirement: キャンセル
ユーザーが「キャンセル」を押した場合、システムはカラムを追加せずにリスト選択画面を閉じ、元のカラム表示に戻らなければならない(MUST)。

#### Scenario: キャンセル
- **WHEN** リスト選択画面でリストを開いた状態で「キャンセル」を押す
- **THEN** リスト選択画面が閉じ、カラム構成は変わらない

### Requirement: リスト選択画面の制約
リスト選択画面は、カラムビューと同じ隔離設定(sandbox・contextIsolation 有効、preload なし)とナビゲーション制御(x.com 以外への遷移と新規ウィンドウは既定ブラウザへ回す)に従わなければならない(MUST)。システムはリスト選択画面に対してスクリプト実行・CSS 注入・DOM やページタイトルの読み取り・自動操作を行ってはならない(MUST NOT)。

#### Scenario: 外部リンク
- **WHEN** リスト選択画面で x.com 以外へのリンクをクリックする
- **THEN** リスト選択画面は遷移せず、そのURLは既定ブラウザで開かれる

#### Scenario: 画面の内容を読まない
- **WHEN** リスト選択画面でリストを開いて追加する
- **THEN** カラムのタイトルはリスト名ではなく「リスト <数字>」となり、アプリは URL 以外の情報を使用しない

### Requirement: 未ログイン時は開けない
ログイン画面を表示している間(カラム画面に移る前)は、リスト選択画面を開いてはならない(MUST NOT)。

#### Scenario: ログイン前の操作
- **WHEN** ログイン画面の表示中に、リスト選択画面を開く要求が届く
- **THEN** リスト選択画面は開かれない
